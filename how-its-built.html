Portfolio demo · How it’s built

A real ordering system on a small-business budget

The brief: let customers order custom cookies and book classes online, around a home baker’s real limits; take payment; and give the owner one place to run it all from her phone, with no monthly software bill and nothing she has to maintain.

$0a month for hosting, database and email
~7,800lines of hand-written code, no framework
300+automated checks on the server rules
2environments: test and live, kept identical

How the pieces fit

WebsiteStatic HTML, CSS and JavaScript on Cloudflare Pages. Menu, checkout, classes, contact.
ServerGoogle Apps Script: checks every order against the rules, sends emails, runs a 5-minute background check and a daily health check that emails the owner only when something needs fixing.
DataA Google Sheet: orders, messages, settings, codes. The owner can open it like any spreadsheet.
Owner adminServed by Apps Script, only to the owner’s Google account. Its look and logic load from the website.
QuickBooks OnlineInvoices for cookie orders, with automatic sales tax and an online Pay button.
SquareInstant card checkout for class bookings, with a timed hold on the spot.
Customer → website → server → SheetThe website never holds secrets. Payment keys live only in the server’s private settings, and the server re-checks everything the website sends.

Why each piece

Plain HTML, CSS and JavaScript

Instead of: React, a site builder, or an ecommerce platform

The site is small, but the rules are unusual (weekly baking limits, flavor limits, ZIP-based drop-off, class holds), which off-the-shelf shops don’t handle. Plain files load fast, have no build step or dependencies to update, and will still run in ten years. Shared pieces (the bag, header, settings loader) are reused across every page.

Google Sheet + Apps Script as the back end

Instead of: a database and a hosted server

It’s free, it runs on Google’s infrastructure, and the owner can see and fix her own data in a tool she already knows. Google handles the admin’s login: only her account can open it. Emails go out from her own Gmail, so replies come straight back to her.

QuickBooks for cookie orders, Square for classes

Two payment tools, on purpose

Cookie orders need a human in the loop: she reviews each one, adjusts the price, then invoices. QuickBooks was already her accounting tool, and it works out sales tax by address. Classes are fixed-price and first-come, so they need instant payment; Square’s checkout links handle that, with the server holding the spot for 15 minutes and releasing it (and closing the link) if payment doesn’t come through.

An admin built for a phone

Instead of: editing a spreadsheet

Every setting the site uses (prices, flavors, lead time, weekly limits, blocked dates, drop-off ZIPs, wording, photos, events, codes) is editable in plain language, with a preview before going live. Orders, messages, phone orders, pickup times and payments all happen in one place, with toasts and confirmations sized for a phone.

Cloudflare Pages + GitHub

Hosting and release process

The live site is on Cloudflare Pages with her own domain; a test copy runs on GitHub Pages against a separate test Sheet, test QuickBooks and Square sandbox. Changes go to test first, pass a written test plan, then get promoted to live by moving one branch.

Details that matter

Speed

Settings are remembered in the browser, so return visits open instantly and refresh quietly in the background. First visits fade in once real settings arrive, so customers never see stale prices.

Reliability

Every rule is enforced twice: in the browser for instant feedback, and on the server so nothing can be bypassed. Orders are protected against double-clicks and dropped connections. A background check every 5 minutes marks invoices paid, expires unpaid class holds, and sends pickup reminders the morning before.

Privacy

The pickup address only appears in confirmation emails. Customer data stays in her Google account. Payment keys are stored only in the server’s private settings, never in the website.

Testing

The server code runs in automated tests with Google’s services stubbed out (over 300 checks covering ordering rules, payments, reminders, emails and phone orders), plus a written end-to-end test plan run on the test site before each release.

Accessible and mobile-first

Built for phones first: one-row header, full-width tap targets, no zoom traps. Keyboard focus, labels and screen-reader text throughout.
